# Market Basket Analysis

## 📌 Project Overview

This project performs **market basket analysis to identify product pairs that are frequently purchased together** using transaction-level sales data.

The analysis focuses on identifying **co-purchase relationships between items within the same transaction**, ranking the strongest item pairs, and identifying highly connected items that frequently appear across multiple product combinations.

The results provide insights that can support **product bundling, cross-selling, product recommendations, and product placement strategies**.

The analysis was conducted using **Google BigQuery (GoogleSQL)** with CTEs, self-join, conditional pair matching, aggregation, grouping, and pair deduplication logic.

---

## 🗂️ Dataset

The analysis uses item-level transaction records from the `privat-class.course1.item` table.

### Key Columns

| Column       | Description                                                |
| -------------| ---------------------------------------------------------- |
| `invoice`    | Unique transaction/invoice identifier                      |
| `item_code`  | Unique product identifier                                  |
| `qty`        | Quantity of the product purchased in a transaction         |  
| `net_amount` | Net sales amount generated by the product in a transaction |

### Analysis Scope

The analysis evaluates products purchased within the **same invoice** to identify item pairs that frequently occur together.

The analysis covers:

* **619 unique items**
* **2,211 unique item pair combinations**
* **45,290 co-purchase events**

Only item pairs with at least **10 co-purchases** are included in the final ranked output.

---

## 🔗 Data Relationship

The analysis uses the transaction identifier to identify products purchased within the same basket.

```text
invoice
  │
  ├── item_a
  │
  └── item_b
```

Two different items are considered a co-purchase pair when they appear in the same invoice.

To avoid duplicate representations of the same pair, the analysis applies an ordering condition:

```sql
a.item_code < b.item_code
```

Therefore:

```text
SA015-2 + SA1-1CS
```

and

```text
SA1-1CS + SA015-2
```

are treated as the same product pair.

## 📊 Key Metrics

### Co-Purchase Frequency

Number of distinct invoices in which two different items were purchased together.

```text
Co-Purchase Frequency =
Number of Distinct Invoices Containing Both Items
```

### Unique Item Pairs

Number of distinct combinations of two different items identified across transactions.

### Co-Purchase Events

Total number of co-purchase occurrences across all identified item pairs.

### Item Connectivity

Number of unique product pairs in which a particular item appears.

A higher number indicates that an item is connected to a larger number of other products within customer baskets.

### Total Co-Purchase Volume

The cumulative number of co-purchase events across all product pairs involving a specific item.

This metric helps identify products that act as strong **cross-sell anchors** across the catalog.

## 🧮 SQL Techniques Demonstrated

### 1. CTE (Common Table Expression)

Used a CTE to create a distinct basket containing unique item-invoice combinations before generating product pairs.

```sql
WITH basket AS (
  SELECT DISTINCT
    invoice,
    item_code
  FROM privat-class.course1.item
)
```

This prevents duplicate item records within the same invoice from inflating the co-purchase calculation.

---

### 2. Self-JOIN

The basket was joined with itself to identify two different products purchased within the same invoice.

```sql
FROM basket a
JOIN basket b
  ON a.invoice = b.invoice
```

The self-join allows each product in a transaction to be compared with other products in the same transaction.

---

### 3. Pair Deduplication

The condition:

```sql
AND a.item_code < b.item_code
```

ensures that each product pair is counted only once.

For example:

```text
SA015-2 + SA1-1CS
```

is retained while the reversed combination:

```text
SA1-1CS + SA015-2
```

is excluded.

---

### 4. `COUNT(DISTINCT)`

Used `COUNT(DISTINCT a.invoice)` to measure how many unique transactions contained both products.

```sql
COUNT(DISTINCT a.invoice) AS bought_together
```

This prevents the same invoice from being counted multiple times for a product pair.

---

### 5. `GROUP BY`

Grouped the resulting transactions by product pair to calculate the co-purchase frequency for each combination.

```sql
GROUP BY
  item_a,
  item_b
```

---

### 6. Filtering High-Frequency Pairs

Only pairs with at least **10 co-purchases** were included in the final output.

```sql
WHERE bought_together >= 10
```

This focuses the analysis on recurring product relationships rather than isolated co-purchases.

---

### 7. Ranking Product Pairs

Product pairs were ranked from the highest to lowest co-purchase frequency.

```sql
ORDER BY bought_together DESC
```

This makes it possible to identify the strongest product relationships and prioritize them for business action.
